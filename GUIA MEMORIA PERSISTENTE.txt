================================================================================
GUÍA DE MEMORIA Y PROTOCOLOS DE DESARROLLO - WILLPOVOICE
================================================================================
Este documento contiene las reglas estrictas, lecciones aprendidas y protocolos 
técnicos para el desarrollo, mantenimiento y compilación de WillpoVoice.
El asistente de IA DEBE leer y seguir estas reglas en cada sesión.

--------------------------------------------------------------------------------
1. REGLAS DE ORO PARA MODIFICAR CÓDIGO (ANTI-RUPTURA)
--------------------------------------------------------------------------------
- PROHIBIDO usar comandos de PowerShell con `-replace` multilinea DIRECTAMENTE 
  sobre archivos Python. PowerShell destruye la indentación (tabs/espacios) y 
  altera la codificación (cambia UTF-8 a UTF-16 BOM), lo que rompe el script.

- PROHIBIDO crear archivos de parcheo persistentes como `apply_patches.py`. 
  Este archivo ha sido eliminado del proyecto.

- METODOLOGÍA APROBADA: "Comandos Quirúrgicos con Here-String + Python"
  El asistente debe generar un bloque de PowerShell que:
  a) Use un Here-String (`@' ... '@`) para contener el código Python en memoria
  b) Lo guarde en un archivo temporal con `Set-Content -Encoding UTF8`
  c) Lo ejecute con `.\.venv\Scripts\python.exe archivo_temporal.py`
  d) Opcionalmente lo elimine con `Remove-Item` al finalizar
  
  Esto garantiza que Python (no PowerShell) sea quien modifique el código,
  respetando indentación, codificación UTF-8 y saltos de línea originales.

- Siempre crear un backup (.bak) DENTRO del script de Python antes de modificar.
- El script de Python debe usar `str.replace()` exacto, NUNCA regex multilinea.

2. PROTOCOLO DE COMPILACIÓN (GUIA PARA COMPILAR)
--------------------------------------------------------------------------------
- Herramientas: PyInstaller 6.22.2 (NO actualizar a otra versión) e Inno Setup 6.
- Spec File: Usar SIEMPRE `WillpoVoice_final.spec`.
- Pesos Sagrados (v1.4.0 - modo ONEDIR con modelos incluidos):
  * Modo de compilación: ONEDIR (carpeta dist\WillpoVoice\), NUNCA onefile.
  * EXE (dist\WillpoVoice\WillpoVoice.exe): ~35 MB.
  * Carpeta completa dist\WillpoVoice\: ~1150-1200 MB.
  * Instalador (Setup): ~500-550 MB (v1.4.0 real: 526 MB).
  * Setup > 600 MB = duplicados de modelos colados: limpiar models/ (Sección 7).
  * Setup < 450 MB = faltan modelos o voices: revisar .iss y spec.
  * NO incluir redist\, _models_backup\ ni voices\previews\ en el instalador.

- Reglas del Instalador (Inno Setup - `installer\NaturalVoiceTTS.iss`):
  * NO incluir la carpeta `redist\` en el instalador.
  * SÍ incluir `sapi_adapter\x64\` en `{app}\sapi\x64`.
  * Registrar la DLL en silencio: `regsvr32 /s` (para que NO aparezca en 
    "Programas y características" de Windows).
  * Aplicar automáticamente el archivo `adapter_config.reg` desde `{tmp}` 
    usando `regedit /s` para activar las voces multilingües por defecto.

3. METODOLOGÍA: ADAPTER SAPI Y VOCES
--------------------------------------------------------------------------------
- Herramienta oficial: `NaturalVoiceSAPIAdapter` (Repo: gexgd0419/NaturalVoiceSAPIAdapter).
- REGLA: NUNCA sugerir reemplazar el adapter por librerías como `edge-tts` si el 
  problema se puede resolver configurando el adapter.
- Antes de sugerir parches o workarounds, el asistente DEBE revisar el repositorio 
  oficial en GitHub (Issues y Releases) para ver si es un bug conocido o un cambio 
  de endpoint de Microsoft.
- Configuración Mágica (adapter_config.reg):
  [HKEY_CURRENT_USER\SOFTWARE\NaturalVoiceSAPIAdapter\Enumerator]
  "EdgeVoiceAllLanguages"=dword:00000001
  "EdgeVoiceAllMultilingual"=dword:00000001
  Esto garantiza que aparezcan las 300+ voces (Florian, Giuseppe, etc.).
- Error "Invalid HTTP status" al exportar o al speak: DOS causas posibles:
  (a) bloqueo local de Firewall/Antivirus/Proxy de conexiones wss://;
  (b) desde el 10-oct-2026: Microsoft migro Sec-MS-GEC a v2 y los nodos
  rechazan el handshake v1 con 403 (v0.2.10 es fix parcial; el fix completo
  es PR #121 / build gec-v2). Discriminar con test objetivo: speak sincrono
  con voz Online; muere en <1 s con COMException = (a) o (b); probar en una
  segunda red ANTES de tocar codigo, registro o DLLs.
  de Firewall, Antivirus (Defender) o Proxy en la PC del cliente que bloquea 
  las conexiones WebSocket (wss://) a Microsoft Edge TTS.

5. OPTIMIZACIÓN DE RENDIMIENTO (PREVISUALIZACIÓN)
--------------------------------------------------------------------------------
- El `PreviewWorker` no debe iterar las 300+ voces de SAPI en cada clic.
- Implementar un caché de tokens (`self._voice_cache = {}`) dentro del hilo 
  para guardar la voz buscada la primera vez.
- Implementar un "Warm-up" silencioso (`sapi.Speak("", 1)`) al iniciar el worker 
  para eliminar el "Cold Start" (retraso de 1-2 segundos en el primer clic).
- El Cold Start se debe a que el adapter debe: resolver DNS, establecer TLS, 
  autenticarse con token JWT y abrir canal WebSocket la primera vez.

6. METODOLOGÍA: COMANDOS QUIRÚRGICOS (PLANTILLA ESTÁNDAR)
--------------------------------------------------------------------------------
- Formato estándar para cualquier parche futuro:

  $pyScript = @'
  from pathlib import Path

  file = Path("ui/modern_window.py")
  if not file.exists():
      print("Error: No se encuentra ui/modern_window.py")
      exit(1)

  backup = file.with_name(file.name + ".bak_NOMBRE_DEL_FIX")
  if not backup.exists():
      file.replace(backup)
      print("✅ Backup creado: " + backup.name)
  else:
      print("ℹ️  Usando backup existente")

  content = backup.read_text(encoding="utf-8")
  changes = 0

  old = """BLOQUE_EXACTO_DEL_CODIGO_ORIGINAL"""
  new = """BLOQUE_NUEVO_DE_CODIGO"""

  if old in content:
      content = content.replace(old, new)
      changes += 1
      print("✅ Parche aplicado correctamente")
  else:
      print("⚠️  Bloque no encontrado (ya aplicado o código cambió)")

  if changes > 0:
      file.write_text(content, encoding="utf-8")
      print(f"🚀 Éxito: {changes} parche(s) aplicado(s)")
  else:
      print("⚠️  No se aplicaron cambios")
  '@

  Set-Content -Path "fix_temporal.py" -Value $pyScript -Encoding UTF8
  .\.venv\Scripts\python.exe fix_temporal.py
  Remove-Item "fix_temporal.py" -Force

- Reglas del formato:
  * El Here-String usa comillas simples (@' ... '@) para evitar interpolación
  * El script Python SIEMPRE parte del backup (.bak), nunca del archivo actual
  * Usar `str.replace()` exacto, NUNCA regex
  * Copiar el bloque `old` EXACTO del archivo original (incluyendo espacios/tabs)
  * El nombre del backup debe ser descriptivo: `.bak_nombre_del_fix`

8. INTEGRACIÓN DE VOCES CLONADAS EN UI (PREMIUM) - ARQUITECTURA Y ESTADO ESTABLE
--------------------------------------------------------------------------------
- Estado verificado como funcional (NO regredir):
  * Preview SAPI mantiene su velocidad original (PreviewWorker con caché y warm-up).
  * Voces clonadas (ej. "Alfredo") aparecen en Voces -> Premium con foto y badge Pro.

  * Modo expresivo (micro-pausas, boost ¡/¿) aplica SOLO a voces SAPI.

  * Se hace justo después de `self._voices = voices` en el rebuild de voces:

    self._voices = [v for v in self._voices if v not in self._cloned_set] + list(_cloned)

    posteriores de `self._voices = voices`. Inyectar siempre DESPUÉS del punto
    canónico de rebuild (donde se hace el dedup de SAPI).
- Selección: `_select_voice` fija `self._selected_cloned = name` si el nombre
  está en `_cloned_set`; si no, lo deja en "".
- Desvíos (bypass) ACTIVOS y OBLIGATORIOS:
  * `_toggle_preview`: si name in _cloned_set -> `_play_cloned_preview(name)` y return.
  * `_tts_text`: si _selected_cloned -> llama `_tts_cloned(...)` y `return text`
    (DEBE devolver el texto: varios callers SAPI usan su retorno).
  * `speak_text`: si _selected_cloned -> `_tts_cloned(...)` y return (SAPI no habla).
  * `export_wav` / `export_mp3`: si _selected_cloned -> `_export_cloned(text, path, is_mp3)` y return.
  * `_express_segments` / `_show_express_hint`: retornan sin efecto si _selected_cloned.
- Métodos de módulo y sus asignaciones MainWindow (falta asignación =
  AttributeError en runtime; verificar SIEMPRE ambos juntos):
  _play_cloned_preview, _on_cloned_preview_ready, _on_cloned_preview_cached,
  _on_cloned_preview_failed, _tts_cloned, _on_tts_cloned_done,
  _on_tts_cloned_failed, _export_cloned, _on_export_cloned_done,
  _on_export_cloned_failed, _set_card_spin.
- Workers y atributos separados (NUNCA reusar los de SAPI):
  * `_ClonedPreviewWorker(QThread)`: done = Signal(str), failed = Signal(str);
    tiene request_stop() y _stop_requested. Se reusa para preview, TTS y export.
  * Atributos: _cloned_preview_worker, _cloned_tts_worker, _cloned_export_worker.
  * LECCIÓN: reusar `_preview_worker` de SAPI causó AttributeError porque el
    worker SAPI tiene request_stop() y el clonado no (y viceversa).
- Caché de preview instantáneo:
  * Ruta SIEMPRE en zona escribible: %LOCALAPPDATA%\WillpoVoice\previews\

  * Cargar con safetensors.torch.load_file (claves planas
    "transformer.layers.X.self_attn.offset" etc.).
  * REAGRUPAR por los primeros 4 segmentos:
    nested["transformer.layers.X.self_attn"][attr] = tensor.
  * Estructuras INCORRECTAS y sus errores:
    - Dict plano tal cual -> "'Tensor' object has no attribute 'get'".
    - Listas anidadas {"transformer":{"layers":[...]}} -> "Could not find
      offset in model state".
  * ModelState NO existe como clase importable en pocket_tts: no importar.
- generate_with_voice(name, text) devuelve UN solo str (ruta WAV temporal).
  Nunca desempaquetar en 2 valores ("not enough values to unpack").
- Regeneración manual:
  * Script generate_voice.py <ruta_wav> <nombre> (raíz del proyecto).
  * El apartado Clonar voz también guarda huellas (ej. "se mejor_voz.safetensors"):

  * Tamaño ~9 MB del archivo es NORMAL (state completo).
- Procedimiento para cambiar la voz de una huella:
  1) Borrar voices/<name>.safetensors
  2) generate_voice.py "<wav>" <name>  (o renombrar desde Clonar voz)
  3) Borrar %LOCALAPPDATA%\WillpoVoice\previews\*.wav

11. LECCIONES DE ESTABILIDAD Y DIAGNÓSTICO (ANTI-RUPTURA EXTENDIDO)
--------------------------------------------------------------------------------
- Diagnosticar ANTES de parchear: imprimir el bloque exacto con slices de
  Get-Content (Select-Object -Skip N -First M) y copiar `old` literal.
- Si un parche reporta "Bloque no coincide": NO forzar con regex ni variantes
  "parecidas"; re-diagnosticar y copiar el bloque vigente.
- NUNCA usar `python -c "..."` inline con comillas anidadas o backslashes:
  PowerShell los corrompe (SyntaxError). Usar script temporal (Here-String).
- El mojibake en consola (ðŸ§¬, âšï¸) es artefacto de DISPLAY de PowerShell
  leyendo UTF-8 como ANSI: el archivo tiene emojis reales; en los strings
  `old` se escriben los emojis reales.
- Verificar sintaxis tras cada parche: py_compile.compile(..., doraise=True);
  si falla, restaurar desde el backup (shutil.copy2).
- Signals de QThread: mantener aridad consistente (done emite 1 str;
  los handlers reciben 1 argumento).
- Proliferación de backups: hay muchos .bak_* en ui/ y core/. Riesgo
  detectado: el archivo real puede quedar ELIMINADO existiendo solo backups
  (pasó con core/pocket_cloner.py). Procedimiento de restauración: copiar el
  backup más reciente (Sort-Object LastWriteTime -Descending | Select -First 1)
  y verificar bloques esperados antes de continuar.
- No mezclar flujos SAPI y clonado en mismos atributos/workers (ver sección 8).
- Tras tocar listas de voces: verificar que la velocidad SAPI no cambió
  (regla 5) y que Alfredo sigue apareciendo en Premium.

- En modo compilado windowed (console=False) o con stdout redirigido,
  sys.stdout usa cp1252 o es None: cualquier print() con emoji lanza
  UnicodeEncodeError/AttributeError DENTRO del worker y mata la generación
  (síntoma en cliente: "bucle" de carga sin mensaje). Fix permanente en
  run.py: reconfigurar stdout/stderr a UTF-8 con errors="replace" (o
  devnull si son None) justo tras `from __future__ import annotations`.
  En consola de desarrollo NO se reproduce (PEP 528: consola = UTF-8).
- Toda librería que lea config en runtime (YAML/JSON dentro de su propio
  paquete) necesita collect_data_files(pkg) en el spec. PyInstaller copia
  los .py pero NO el package data: en frozen aparece
  "FileNotFoundError: config/*.yaml ... Available languages: []" aunque en
  dev funcione. Caso real: pocket_tts (v1.4.0). GATE obligatorio post-build:
  Get-ChildItem dist\WillpoVoice\_internal\<pkg>\config debe listar los
  YAMLs ANTES de correr ISCC.
- Restaurar un archivo desde .bak revierte TODOS los parches aplicados
  después de ese backup (v1.4.0: el restore a console=False se llevó el
  collect_data_files("pocket_tts") y el instalador salió roto). Regla: tras
  cualquier restore, re-verificar marcadores críticos antes de compilar.
- dist\ NO es el layout instalado: onedir solo produce EXE + _internal\.
  Las carpetas sapi\x64\ y voices\ las crea el ISS en {app}. Para probar un
  build frozen local, replicar ambas en dist\WillpoVoice\; si no, falso
  negativo: 3 voces Desktop y sin clonadas.
- El registro del NaturalVoiceSAPIAdapter es POR MAQUINA: si una PC muestra
  3 voces Desktop (COM count = 3), re-registrar con regsvr32 /s desde
  installer\sapi_adapter\x64\ y aplicar adapter_config.reg con regedit /s.
  No es bug del build (v1.4.0: pasaba en dev, no en cliente).
- Técnica de diagnóstico frozen: compilar temporalmente con console=True,
  lanzar con Start-Process -RedirectStandardOutput/-Error y prints con flush
  en el worker; al terminar, restaurar spec y modern_window (ver lección de
  restores). NUNCA dejar console=True en release.
- Las copias adjuntas o transcripciones pueden perder sangrías: extraer el
  bloque old del archivo EN DISCO (anclas + rango de líneas), nunca de
  copias normalizadas.
- Incidente Sec-MS-GEC (10-oct-2026): Microsoft migro el token DRM de v1 a v2;
  los nodos rechazan el handshake v1 con 403 ("Invalid HTTP status" en el
  adapter). v0.2.10 es fix parcial (solo URL); el fix completo es PR #121
  (build gec-v2). Verificar SIEMPRE el repo oficial antes de parchear codigo.
- Test objetivo de sintesis online: speak SINCRONO (flag 0) con cronometro;
  vivo = sin excepcion y > 1.5 s; muerto = COMException "Invalid HTTP status"
  o state 2->1 en < 1 s. El retorno de Speak (1) NO indica exito.
- Post-condicion por hash tras copiar DLLs/binarios: Get-FileHash destino ==
  hash fuente. Un check impreso sin verificar causo dos diagnosticos falsos.
- Copias a C:\Program Files exigen PowerShell elevado; sin elevacion el error
  es "Acceso denegado" y el flujo sigue con el binario viejo registrado.
- Catastrofe del 29-oct-2026: un git reset --hard origin/main con trabajo sin
  commitear borro core/pocket_cloner.py, voices/Alfredo.safetensors y la UI
  moderna del arbol. Rescate: tag v1.5.0 (arbol completo) + commit colgante
  9540fc6 (guias rev.6). Leccion: commitear antes y restaurar ARBOL COMPLETO
  desde el tag bueno, nunca archivos sueltos (los arboles parciales rompen
  imports y activan fallbacks silenciosos como la UI legacy v1.3.0).
- Los pesos del motor (~418 MB) NUNCA estan en Git (limite 100 MB). En

  en models\pocket_tts\hub. Tras filter-repo/reset, restaurar el hub desde

14. MODO ONEDIR VS ONEFILE (DECISIÓN TÉCNICA v1.4.0)
--------------------------------------------------------------------------------
- onefile DESCARTADO: con modelos incluidos el EXE pesa ~1 GB y arranca en
  4-6 s descomprimiendo todo en _MEIxxxxx (carpeta temporal); riesgo de
  corrupción si el usuario cierra durante la descompresión.
- onedir (ACTUAL): el spec usa COLLECT() y genera dist\WillpoVoice\ (carpeta).
  Arranque 2-3 s; el ISS copia "..\dist\{#MyAppName}\*" con recursesubdirs.
- Consecuencias obligatorias:
* NO subir dist\WillpoVoice.exe suelto a GitHub Releases: no funciona sin
  _internal\. Subir SOLO el Setup del instalador (~526 MB).
* Spec: EXE(..., [], exclude_binaries=True) + COLLECT(exe, a.binaries, a.datas).
* El instalador es la única unidad de distribución del producto.

15. PROTOCOLO GIT ANTI-PERDIDA (OBLIGATORIO ANTES DE OPERACIONES DE RIESGO)
--------------------------------------------------------------------------------
- NUNCA ejecutar git reset --hard, filter-repo o checkout masivo con trabajo
  sin commitear: verificar antes con git status --porcelain (vacio o revisado).
- Antes de push/reset/filter-repo: crear tag de seguridad local:
  git tag backup-<fecha>-<motivo> (ej. backup-2026-10-29-pre-release).
- Commitear SIEMPRE el trabajo del dia antes de tocar remotes o historial.
- Maquinas del tiempo validadas (en orden): tag de release (v1.5.0 conservo
  pocket_cloner y Alfredo cuando main los perdio) > commit colgante de
  reflog/fsck (9540fc6 rescato las guias rev.6) > backup .bak en disco.
- Si un reset/checkout pierde archivos: restaurar ARBOL COMPLETO desde el tag
  bueno (git checkout <tag> -- .), no archivos sueltos.
- Tras cualquier restauracion: correr scripts/gate_regresion.py ANTES de
  compilar o liberar; y re-verificar marcadores criticos (Seccion 11).
